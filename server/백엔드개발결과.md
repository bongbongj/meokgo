# 남은 백엔드 개발 결과

작성자: 정효림  
작성일: 2026-11-06

## 1. 참조 문서와 적용 범위

- [API 명세서](../reference/API명세서.md): 4절 홈, 12절 사용자 통계·기록, 13절 스토리, 16절 저장·보관 정책을 참조했다.
- [DB 설계서](../reference/DB설계서.md): 6.14~6.20절 기록·사진·스토리·리텐션 테이블과 8~10절 정책을 참조했다.
- 현재 저장소의 스프링부트 서버에 남은 기능을 추가했다. 호스트 앱과 참여자 웹 프로젝트는 포함하지 않았다.
- 기존 참조 문서의 사진 미구현 안내와 이전 README의 다음 구현 순서는 이번 개발 이전 상태다. 이 문서에 현재 추가한 동작과 기본 정책을 기록했다.

## 2. 구현한 기능

| 영역 | 동작 |
| --- | --- |
| 홈 | 최근 참여한 활성 탐험방, 본인 완료 수, 현재 참여자 수, 최근 개인 기록 3개, 인기 지역 3개, 리텐션 요약 |
| 통계 | 종료한 개인 탐험 기록 수, 개인 퀘스트 완료 이력 수, 중복을 제외한 방문 지역 수 |
| 인기 지역 | 종료한 탐험방 수로 집계하며 같은 방의 참여자별 기록을 중복으로 세지 않음 |
| 리텐션 | 단계 마스터와 사용자 달성 이력 저장, 탐험 종료 시 반영, 기존 기록의 조회 시 보완, 동시 요청 중복 방지 |
| 템플릿 | 기본 템플릿 초기 등록, 활성 템플릿 목록과 실제 미리보기 PNG 제공 |
| 사진 | 실제 PNG·JPEG 검사, 크기 제한, PNG 재인코딩, 기록별 사진 1~4장 업로드, 개인별 파일 조회 |
| 스토리 | 선택한 사진 순서·지역·탐험 종료 날짜·본인 완료 퀘스트·메모로 1080×1920 PNG 생성 |
| 보관 | 사진 업로드·이미지 생성 각각 30일 후 접근 차단, 만료 파일 삭제와 삭제 상태 기록 |
| 오류 복구 | DB 롤백 시 새 파일 정리, 파일 삭제 실패 시 다음 정리 실행에서 재시도 |

홈의 활성 방은 종료·만료·이탈 상태를 제외하고 가장 최근 참여한 방을 선택한다. 퀘스트 확정 전에는 예정 개수인 3개를 표시한다. 홈의 현재 단계나 다음 단계가 없으면 해당 필드는 `null`이다.

## 3. 리텐션 기본 정책

참조 문서에는 세 가지 단계 코드와 일부 예시만 있으며, 전체 달성 수치와 보상 지급 방식은 확정되어 있지 않다. 다음은 이번 구현에서 적용한 검토 가능한 기본값이다.

| 코드 | 단계 | 기본 달성 기준 |
| --- | --- | --- |
| `FIRST_DISCOVERY` | 첫 발견 | 탐험을 처음 종료함 |
| `ALLEY_EXPLORER` | 골목 탐험가 | 같은 지역의 탐험을 서로 다른 2일에 종료함 |
| `REGION_MASTER` | 지역 마스터 | 같은 지역의 탐험을 서로 다른 3일에 종료함 |

날짜는 탐험 기록 생성 일시의 날짜를 사용한다. 퀘스트가 미완료여도 정상 종료한 탐험은 집계한다. 같은 날짜의 반복 탐험은 재방문 날짜 수를 늘리지 않는다. 각 단계는 사용자별 최초 1회 달성하며 지역 기반 단계에는 처음 달성한 지역을 저장한다.

지역 마스터 기준은 `RETENTION_REGION_MASTER_VISIT_DAYS`로 변경하며 최소 3일이다. 재시작 시 단계의 조건 안내 문구도 설정과 맞춘다. 이미 저장한 달성 이력은 기준을 변경해도 취소하지 않는다. 보상은 현재 설명과 달성 상태로 제공하며 별도의 퀘스트 세트 잠금 해제나 실물 보상 지급을 수행하지 않는다.

## 4. 추가 API와 사용 흐름

모든 API와 이미지 URL 요청에는 기존 `X-Device-Key` 헤더를 포함한다.

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| GET | `/api/v1/home` | 홈 |
| GET | `/api/v1/users/me/statistics` | 개인 통계 |
| GET | `/api/v1/story-templates` | 활성 템플릿 목록 |
| GET | `/api/v1/story-templates/{template_id}/preview` | 템플릿 미리보기 PNG |
| POST | `/api/v1/records/{record_id}/photos` | 사진 업로드 |
| GET | `/api/v1/records/{record_id}/photos/{photo_id}/content` | 개인 사진 PNG |
| POST | `/api/v1/records/{record_id}/story-image` | 스토리 생성 |
| GET | `/api/v1/records/{record_id}/story-image/{story_image_id}` | 스토리 정보 |
| GET | `/api/v1/records/{record_id}/story-image/{story_image_id}/content` | 스토리 PNG |

사진 업로드는 `multipart/form-data`의 `photos` 필드로 전달한다. 업로드 요청 자체를 스토리 제작 선택으로 처리하고 기록의 `story_selected_yn`을 켠다. 여러 번 요청해도 기록당 유효 사진은 최대 4장이다. 만료된 사진은 수량에서 제외하며, 새 사진에는 이전과 겹치지 않는 순서를 부여한다.

생성 요청은 명세의 `template_id`, `photo_ids`, 선택값인 `image_ratio`, `memo`를 받는다. 비율은 생략하거나 `9:16`을 사용한다. 메모는 최대 500자이며 카드에 표시할 수 있는 범위까지 줄바꿈해 표시한다. 긴 제목과 퀘스트 문구는 표시 폭에 맞춰 생략한다. `photo_ids`는 중복 없이 본인 해당 기록의 유효 사진만 전달한다.

반환 URL은 서버 기준 상대 경로다. 클라이언트는 API 서버 주소를 붙이고 기기 헤더를 포함한 요청으로 바이트를 내려받아 표시·저장·공유한다. 원본 파일을 공개 정적 경로로 제공하지 않는다. 개인 이미지 응답에는 캐시 금지 정책을 적용한다.

기록 상세의 `photos`에는 현재 유효한 업로드 사진을 순서대로 반환한다. 다른 사람의 기록에는 기존과 같이 `RECORD-001`을 반환한다.

## 5. 저장과 실행 설정

명세에서 허용한 초기 로컬 저장을 사용한다. `storage_provider`는 `LOCAL`이며 S3 연결은 포함하지 않았다. 파일명은 서버에서 생성하므로 사용자가 전달한 경로나 원본 파일명으로 저장하지 않는다.

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `STORAGE_LOCAL_ROOT` | `./storage` | 개인 사진·스토리 PNG 저장 디렉터리 |
| `STORAGE_CLEANUP_DELAY_MS` | `3600000` | 만료 파일 정리 실행 간격 |
| `STORY_FONT_FAMILY` | `SansSerif` | 서버에 설치된 한글 지원 글꼴 |
| `RETENTION_REGION_MASTER_VISIT_DAYS` | `3` | 지역 마스터 달성에 필요한 서로 다른 종료 날짜 수 |

파일당 최대 10MB, 전체 요청 최대 41MB를 허용한다. 실제 이미지 헤더에서 최대 2천만 픽셀을 검사하고 저장 시 긴 변을 최대 2048픽셀로 축소한다. PNG 재인코딩으로 원본 메타데이터를 유지하지 않는다. 휴대폰의 HEIC 파일은 현재 지원하지 않으므로 클라이언트에서 PNG·JPEG로 변환해 전송한다.

이미지 정리는 서버 시작 1분 뒤부터 기본 1시간 간격으로 실행하며 한 번에 사진 100개와 스토리 100개까지 처리한다. 삭제가 늦어져도 만료 시각부터 조회와 사진 재사용을 차단한다. 로컬 저장 디렉터리는 Git 추적에서 제외했다. 재배포 시 보관 파일을 유지하려면 해당 경로에 영속 디스크를 연결한다.

리눅스 등 배포 환경에는 한글 글꼴을 설치하고 `STORY_FONT_FAMILY`에 해당 글꼴명을 지정한다. 개발 환경에서는 생성 카드의 한글·영문·숫자를 육안으로 확인했다.

## 6. DB와 오류 응답

추가한 테이블은 `record_photo`, `story_template`, `story_image`, `retention_stage`, `user_retention_stage`다. 기존 `exploration_record`의 스토리 선택 여부와 메모 필드를 연결했다. 기존처럼 JPA의 `ddl-auto: update` 설정으로 테이블을 생성한다. 실제 운영 MySQL 적용은 이번 H2 테스트와 별도로 확인해야 한다.

사진 순서는 기록별 유일 제약을 적용하고, 단계 달성 이력은 사용자·단계별 유일 제약을 적용했다. 만료 정리에는 삭제 여부·만료 시각 인덱스를 추가했다. 업로드·스토리 생성은 기록 잠금으로, 달성 이력은 사용자 잠금으로 직렬화한다.

| 코드 | 상태 | 설명 |
| --- | --- | --- |
| `FILE-001` | 400 | 기존 파일 형식·개수 오류, 잘못된 사진 선택 |
| `FILE-002` | 500 | 추가: 저장소 읽기·쓰기·삭제 실패 |
| `FILE-003` | 410 | 추가: 만료되었거나 삭제된 파일 |
| `STORY-001` | 400 | 기존 스토리 제작 미선택 |
| `STORY-002` | 404 | 추가: 해당 기록의 스토리 이미지 없음 |

신규 오류 코드는 기존 명세의 빈 부분을 보완한 구현 사항이다. 참조 명세 원문에는 아직 반영하지 않았다.

## 7. 검증 및 남은 외부 작업

전체 서버 테스트와 신규 통합 테스트로 다음 항목을 검증했다.

- 신규 사용자의 빈 홈·통계, 미등록 사용자와 헤더 누락 거부
- 본인 통계, 인기 지역의 참여자 중복 제외, 활성 방 복귀와 만료 방 제외
- 같은 날 재탐험 제외, 다른 날 재방문과 지역 마스터 달성, 달성 이력 중복 방지
- 사진 업로드·개인 기록 상세 연결·스토리 생성·PNG 내려받기
- 실제 1080×1920 이미지 크기, 큰 원본 사진 축소
- 타인 접근, 다른 기록의 사진, 중복 사진, 지원하지 않는 비율, 가짜 이미지 거부
- 네 장 제한과 동시 업로드, 트랜잭션 롤백 시 파일 정리
- 만료 시 접근·재사용 차단과 실제 파일 삭제
- 기존 탐험 시작·진행·종료 및 투표 동시성 회귀 테스트

실행 명령은 서버 디렉터리의 `./gradlew test --offline`이다. 렌더링 확인용 이미지는 테스트 후 `build/experience-preview/스토리카드.png`에 생성한다.

운영 지역과 퀘스트의 실제 문구·조건은 참조 문서대로 별도 검수가 필요하므로 기존 개발용 데이터를 임의로 운영 데이터로 바꾸지 않았다. S3 계정·버킷 연결, 운영 MySQL 검증, 배포, 호스트 앱과 참여자 웹 화면·API 연동은 이번 백엔드 구현 결과에 포함하지 않는다.
